# The FIBEN catalog

The queries and the schema of the FIBEN benchmark (decision 149), the third reference domain of
the tool, generated by `FibenImport` from the benchmark's files and committed; nothing here is
edited by hand, and a rule of the conversion changes in the tool, which is then run again.

FIBEN was published by IBM Research as the repository `IBM/fiben-benchmark` under the Apache
License 2.0, whose text is `LICENSE.txt` here (J. Sen et al., *ATHENA++: Natural Language
Querying for Complex Nested SQL Queries*, PVLDB 13(11), 2020). The repository is no longer on
GitHub; everything below was derived from its commit `96eaffc` (2020-12-06). The files in this
folder and those in `database/fiben/` named below are derivative works of the benchmark and
stay under that licence; the tool's own licence does not replace it.

| What | Source | Licence |
|---|---|---|
| `queries.json` - the benchmark's distinct SQL queries, each with its questions in natural language, in T-SQL and, as `benchmarkSql`, in the benchmark's own text | `FIBEN_Queries.json` | Apache-2.0, the text in `LICENSE.txt` |
| `Entities/*.cs` - the Dapper entity class of every table of the FIBEN schema | the tables and columns of `FIBEN.sql` | Apache-2.0 |
| `database/fiben/schema.sql`, `load.sql`, `constraints.sql` - the `Fiben` database of the container | `FIBEN.sql` | Apache-2.0 |
| `database/fiben/judge.tsv` - the rows the catalog's texts return over the data, from a documented run of the tool | the data below | the tool's own file over Apache-2.0 data |
| the data the texts run over - not in the repository | `data.zip` of the same commit; the database image downloads it while it is built, from the release `data_sets` of this repository, where the licence text lies beside it, and `database/fiben/load-fiben.sh` loads it on the first start | Apache-2.0 |

**What changed on the way, and nothing else.** The benchmark writes its schema and its queries
for Db2; here both are T-SQL for SQL Server.

- **The schema** keeps every table, column, primary key and foreign key. The types follow the
  Db2 declarations in their SQL Server spelling, and every text column compares binary, as Db2
  compares it; the header of `database/fiben/schema.sql` lists the mapping.
- **The queries** are carried from the Db2 dialect into T-SQL by a few mechanical rules, and a
  text the rules do not carry over whole - one the benchmark published with a missing
  parenthesis or quote, one SQL Server refuses - is patched by name with the reason. A scope
  sliced by a row limit whose ordering does not determine its rows gets the missing keys appended
  to its ordering, behind the benchmark's own (decision 170). Every rule and every patch is
  written down in `FibenImport/Queries.cs` and nowhere else, and `benchmarkSql` keeps the
  benchmark's text beside each converted one, so every difference can be read off the catalog.
- **The questions** are the benchmark's, unchanged; the paraphrases of one query are gathered
  under it.

Nothing here is compiled: `SampleData.csproj` removes the folder from compilation and embeds
every file in the assembly; `FibenSample` reads them and `ORMConvertorAPI/Data/Fiben.cs` serves
them at `/fiben`.
