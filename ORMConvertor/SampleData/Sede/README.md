# The SEDE catalog

The human-reviewed queries of the SEDE set (decision 208), the fourth reference domain of the
tool, generated by `SedeImport` from the set's files and committed; nothing here is edited by
hand, and a rule of the conversion changes in the tool, which is then run again.

| What | Source | Licence |
|---|---|---|
| `queries.json` - the queries of the validation and the test part of the set, each with the title and the description its author wrote | [hirupert/sede](https://github.com/hirupert/sede), `data/sede/val.jsonl` and `test.jsonl` at commit `2bf2612` (M. Hazoom, V. Malik, B. Bogin, *Text-to-SQL in the Wild: A Naturally-Occurring Dataset Based on Stack Exchange Data*, NLP4Prog 2021) | Apache-2.0, the text in `LICENSE.txt` |
| `Entities/*.cs` - the Dapper entity class of every table of the SEDE schema | the columns of `stackexchange_schema/tables_so.json` of the same checkout; the foreign keys and the type tables from the schema documentation of SEDE (answer 2678 on meta.stackexchange.com, CC BY-SA 4.0, kept as `SedeImport/Schema/documentation.html`) | Apache-2.0; the documentation CC BY-SA 4.0 |
| the data the texts run over - not in the repository | the public data dump of dba.stackexchange.com of 2024-04-06, as Stack Exchange uploaded it to the item `stackexchange` on archive.org; the database image downloads it while it is built (`database.Dockerfile`) and `database/sede/load-sede.sh` loads it on the first start | CC BY-SA 4.0, content by the users of the site, attribution in the loader and on the page of the catalog |

**What changed on the way, and nothing else.** A text stays its author's, mistakes included;
the one change is the placeholders of the Data Explorer, which become parameters: `##Name##`,
`##Name:type##` and `##Name:type?default##` become `@Name`, inside a string literal as a
concatenation, in the row count of a `TOP` in parentheses, and with the prefix `p_` where the
text declares a variable of the same name. A parameter takes the author's default or a value
chosen once over the data (`SedeImport/Values.cs`). The title and the description are
whitespace-normalized. Every query carries its status: *as specified* for one valid read over
the schema, *not translated* with the reason for a script, a text that does not parse or is not
valid over the schema, a text that fails over the data with its values, or a result no typed
target can carry because a column of it has no name or two share one.

Nothing here is compiled: `SampleData.csproj` removes the folder from compilation and embeds
every file in the assembly; `SedeSample` reads them and `ORMConvertorAPI/Data/Sede.cs` serves
them at `/sede`.
