# The differential matrix (decision 089). One section per query; the pairs of the
# criterion are a source variant of the query against each framework that neither states
# it nor refuses it. The six queries the matrix began with have one source each and make
# thirty pairs; the categories of T2 below have every source that states them.
#
# Read by both suites from this one file, beside the schema script - the mechanism
# decision 076 set up so that the schema stays one. The format is deliberately poorer
# than JSON: two parsers in two languages have to agree about it, and a line of
# "key = value" cannot be read two ways.
#
#   source          the framework the query is written in. Its own run is what fixes the
#                   canonical result; every other framework is a pair against it.
#   units           the input files of a conversion, entity units first, query unit last.
#                   A MyBatis mapper is both at once (decision 081), so it appears once.
#   fields          the fields of a result row, in the order the canonical form states
#                   them. A by-name target reads these names off the entity, a positional
#                   one reads by index; both give the same ordered values.
#   shape           entity   - every target returns instances of the generated entity
#                   projection - the targets that project return tuples, and HQL and JPQL
#                               return them positionally
#   ordered         whether the query carries an ordering instruction. When it does not,
#                   both sides sort by the rendered line before comparing.
#   decimalScale    decimal places an exact decimal is rounded to (default 6)
#   floatDigits     significant digits of an approximate number (default 12)
#   arguments       values of the query's parameters, name:type=value (decision 083)
#   mutations       the wrong translations this query can carry (decision 089), of
#                   filter, operator, ordering, rowCount, projection. Stated rather than
#                   discovered, so that a mutation which stops reaching the artifact is a
#                   failure instead of a case that quietly stops running.

# ---- the categories of T2 -------------------------------------------------------------
#
# From here on every section is a category of the shared manifest QueryShapes/categories.txt,
# named by the key below, and states neither a source nor units: the manifest says which
# sources state the category and with which query units, the domain of five entities under
# QueryShapes/entities is the mapping half of every one of them, and the rows they run over
# are QueryShapes/FixtureData.sql. Every source variant of a category runs and has to meet
# the one canonical result of the section, as every translation of it does, so a source
# that read the category into another query is caught by its own run.
#
#   category        the section of categories.txt this query is. A target the manifest lists
#                   under refusedBy is paired with no source of the category and is stated as
#                   a refused direction instead, which a suite asserts (decision 053). A source
#                   the manifest lists under refusedWithoutCatalog is a source here all the
#                   same: the refusal is of a Dapper parameter with nothing to type it from
#                   (decision 083), both suites run with the catalog of the fixture, and the
#                   query asks that catalog for the binding itself, whichever the target
#                   (decision 105) - so the source's own run, the identity direction, runs,
#                   and every category has as many sources as state it (decision 089).
#
# Where none of the five mutations reaches a query, "mutations" is empty and the positive
# half carries the category alone: a target that dropped the DISTINCT of a projection, or the
# DISTINCT inside a COUNT, returns other rows than the canonical ones.
