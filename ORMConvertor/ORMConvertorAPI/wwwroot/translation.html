Translation

Pick the direction, add your source files, convert, and read the artifacts beside what you sent — with every mapping fact's origin and fate, and the records of everything the conversion had to decide, drop or fill in.

1. Direction

Which database system the literal SQL in your source is written for — the text of a SQL query and the literal type of a column. Say “another system” and that SQL is not read at all: a query is refused and a column type is dropped with a record, rather than read as T‑SQL and quietly turned into something else. Framework query languages (LINQ, HQL, JPQL) do not depend on it and are read either way.

2. Input files

An example is a whole conversion input: loading one replaces the units below and sets the direction above. The Examples page explains what each one shows.

    Each artifact names the units it came from and each unit the artifacts it went into: that pairing is the server’s statement. Point at a fact below, or at an underlined word in a panel, and every place the same fact shows itself lights up.

    Facts

    Every mapping fact the conversion held when it generated: which unit stated it, or whether the catalog supplied it or the tool derived it, and whether the artifact carries it. The row and the solid underlines are the server’s word: the reader placed the fact in the unit, the builder marked it in the artifact. Where a framework states no position, the page searches for the fact’s literal value instead and says so — a dotted underline and the words text search beside the value. That search finds a value spelled the same on both sides and misses one the target respells, so a fact without an underline is not a fact that went missing.

    Records

    What the conversion could not carry, filled in by convention, or read from the database catalog. Click a count to show only that kind.
