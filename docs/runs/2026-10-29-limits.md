## Výsledek

8963 bodů .NET půlky v 15 osách, každá řada z každého zdroje, který ji vysloví, do šesti cílů, s fixturou jako katalogem i nasucho; 1077 řádků javové půlky. Žádný bod .NET půlky neběžel nad nezdravou databází — stráž běhu, která by krok zastavila, nezasáhla.

**Překladač** došel ke stropu řady ve všech směrech všech os kromě tří. Nasucho navíc zdroje Dapper a MyBatis do NHibernatu, Hibernatu a EclipseLinku odmítl už první bod, protože bez katalogu nemají klíč (záznam `Failure`, čekané) — ten řádek se níž neopakuje.

Mez S3 (30 s) tedy překlad překročil ve třech řadách: řetěz mezivýsledků ze zdroje EF Core růstem exponenciálním v délce řetězu, 512 joinů ze zdroje EF Core a projekt mezi 1600 a 6400 entitami. Kvadratické průchody, které sondy z 2026-10-26 našly, mez uvnitř stropů nezasáhly nikde.

**Cesta** — co z artefaktu cíl přijme a zda dotaz běží:

| Kde | Řady a body | Čím |
|---|---|---|
| EF Core, kompilace | `subqueries` od 16 `hung` (30 min) ze všech zdrojů; `case` od 2048 a `conditions` 4096 `not compiled`; `joins` 512 `crashed` (výjimka, paměť); `not` 4096 `crashed` | Roslyn: vnořené lambdy se kompilují exponenciálně v hloubce, `CS8078` u výrazu příliš dlouhého |
| EF Core, přijetí a SQL | `expression` 4096 `crashed` | přetečení zásobníku v generátoru SQL EF Core |
| NHibernate, přijetí | `subqueries` od 1024 `crashed` | přetečení zásobníku ve vlastním parseru HQL NHibernatu; řetězy nad 32 články jdou nativním SQL a tam přijetí projde |
| Dapper a nativní SQL, čtení | `case` a `not` 4096 `crashed` | přetečení zásobníku v gramatice ScriptDom, která artefakt čte |
| Hibernate a EclipseLink, kompilace | `conditions` 4096, `case` 2048 `not compiled` | javac: text dotazu přes 64 KB není řetězcová konstanta (`constant string too long`) |
| EclipseLink, přijetí | `conditions` 2048 `not accepted` | výjimka bez zprávy |
| SQL Server, běh | `joins` od 256, `case` nad deset úrovní | plán dotazu nevznikne (chyba 8623); CASE vnořený nejvýš desetkrát (Msg 125) |
| javové instance | řetězy a vnoření od 256 | strop 128 nasazené instance — odmítnutí stropu, ne nalezená mez |

**Javová půlka** posoudila řady `case`, `conditions`, `ctes`, `entities`, `exists`, `expression` a `joins` po bod 256 ze zdroje Dapper; `key-parts`, `nesting`, `not`, `properties`, `relations`, `subqueries`, `unions` a `unit-size` neposoudila a průchod nasucho nezačal. Instance `test_app`, kterou překládá, nemá mez paměti: od 22:02 UTC hlásila hladovění poolu vláken, v 02:17 UTC ji jádro stroje ukončilo pro paměť (`OOMKilled`) a s ní skončila databáze a javová sada. Klient se překladu vzdá po dvou minutách, instance překládá dál, a těžké body — 256 a 512 joinů, pro které SQL Server plán nesestaví — se v ní hromadily.

## Poznámky

- Pokus z 2026-10-27 nad týmž stromem záznam nemá: ve stroji s 8 GB se SQL Server a sada vešly každý pod svou mez, ale ne spolu, a databáze spadla po třech hodinách; odtud rozh. 193.
